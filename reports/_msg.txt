TWO BUGS FOUND, BOTH MINE, BOTH WITH EVIDENCE

1. The ES set was a SUBSET OF ITS OWN TRAINING DATA. The harness fitted the early-stopping model on
   the full outer-fit frame while passing eval_set = f.iloc[es_l]. CatBoost never early-stops in
   that configuration, because the eval metric keeps improving while the model memorises the rows
   it is scored on. Exposed by an arithmetic impossibility rather than a hunch: a SHORTER budget
   with SHORTER patience (2500/200 versus 6000/300) selected 2499 where Phase 10's identical
   configuration selected 1043.
   Verified rather than assumed: the fixed harness reproduces Phase 10 EXACTLY, 0.961067 at 1043
   iterations, and two identical control runs both return 1043 -- so CatBoost IS deterministic here
   and 2499 was a bug, not noise. The harness now aborts if the carve sets overlap or do not
   partition the outer fit. The two contaminated arms are quarantined under
   reports/contaminated_es_leak/ with their logs, and the earlier reading of C4 as -6.9e-5 against
   a budget-matched reference is WITHDRAWN rather than superseded.

2. A cost UPPER BOUND was used as a point estimate, which silently skipped two experiments. The
   projection evaluated cost(R) = a*R + b*R^2 at the 2500-round cap, assuming early stopping never
   fires. C5 and ctr2 therefore "projected" 121 and 132 minutes against a 90-minute budget and
   were SKIPPED, NOT RUN -- quietly, because a cost skip prints as a skip rather than as a failure.
   Their real cost is about 31 and 32 minutes. An upper bound used as a point estimate is not a
   conservative choice, it is a decision made by default, and it removed both arms from Question A.
   The projection now uses the measured stopping point and prints the cap worst case on its own
   line so the upper bound stays visible.

Three further defects introduced while fixing these are recorded too: an UnboundLocalError from `n`
being both a tuple-assignment target and read on the right-hand side; a test that mixed the POSITION
index space with the ROW index space; and an over-strict changed-row count that false-alarmed
because a fold-0 row may legitimately be unchanged. A fourth is a test that asserted on a literal
stop-message string and broke when that message was deliberately rewritten to report measured
quantities -- it was testing wording, not behaviour, and now checks the behaviour.

The report harness also needed a real fix: each counterpart covers only the fold-0 rows while the
blend has 699,635 members, so a raw partial vector cannot be column-stacked (the original crash) and
splicing one naively would silently broadcast. The splice now writes into a full-length copy, leaves
out-of-fold rows byte-identical, asserts the other 58 columns are the original OBJECTS, and verifies
the alpha=0 control reconstructs exactly.
